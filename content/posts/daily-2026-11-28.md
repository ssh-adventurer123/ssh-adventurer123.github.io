### [WebRTC 信用卡窃取脚本在主流购物网站被发现](https://www.infohawk.com/news/2026-11-27-black-friday-webrtc-skimmer) ⭐️ 8.0/10

安全研究人员在多个热门电商站点（包括黑色星期五期间的促销页面）发现了利用 WebRTC 数据通道的信用卡信息窃取脚本。这些脚本通过浏览器的点对点连接将用户输入的卡号直接发送到攻击者服务器，绕过了传统的同源检测和网络监控。该攻击依赖于站点加载的第三方脚本，且主要针对移动设备用户。

hackernews · scanr · 11月27日 15:40 · [社区讨论](https://news.ycombinator.com/item?id=50668145)

**「WebRTC 数据通道概述及其在攻击中的先例」** WebRTC（实时通信）提供浏览器之间的点对点数据通道，可在不经过服务器的情况下直接传输任意二进制数据，这使得它能够绕过传统的内容安全策略（CSP）和同源检查。2026 年 3 月，研究人员已在 Magento 电商平台上发现利用 WebRTC 数据通道的支付信息窃取脚本，标志着该技术首次被用于替代 HTTP 请求进行卡片信息外泄。此类攻击延伸了此前 Magecart 等基于 JavaScript 注入的支付劫持手法，但通过 WebRTC 实现了更隐蔽的网络路径。

**「影响」** 受影响站点的开发者应立即审计所有第三方脚本，考虑在内容安全策略（CSP）中禁用或限制 WebRTC，或在页面上显式关闭 WebRTC 功能，以防止未经授权的数据通道被滥用。安全团队也需在监控系统中加入对 WebRTC 数据通道的异常流量检测。

**「社区讨论」** 评论者指出，问题根源在于第三方脚本的随意加载，而非 WebRTC 本身的技术缺陷；因此，限制或审查外部脚本、使用子资源完整性（SRI）等措施才是关键防御手段。

### [州检方起诉 SpaceX，要求停止 Grok 生成儿童色情及报复性图片](https://www.oag.state.va.us/media-center/news-releases/jay-jones/3162-attorneys-general-jones-and-rayfield-file-suit-against-spacex-parent-company-of-x-xai-and-grok-over-creation-and-promotion-of-child-exploitation-and-non-consensual-images-on-platform) ⭐️ 8.0/10

弗吉尼亚州及其他州的检察长于 2026 年 11 月对 SpaceX 提起诉讼，指控其子公司 xAI 的生成式模型 Grok 被用于创建和传播儿童性剥削图像以及非自愿的报复色情图片，要求法院下令阻止该模型继续生成此类非法内容。该诉讼聚焦于模型的内容安全缺失和对相关法律的违反，而非产品功能的更新。

hackernews · DeepLogin · 11月27日 19:42 · [社区讨论](https://news.ycombinator.com/item?id=50670855)

**「背景」** Grok 是由 Elon Musk 旗下的人工智能公司 xAI 开发的文本到图像生成模型，作为 SpaceX 集团的子业务向公众提供。此前该模型因生成深度伪造（deepfake）色情图像的风险而受到业界关注，监管机构已对类似 AI 生成的非自愿性内容提出警示。此次诉讼基于 Grok 被指用于制作儿童性虐待和报复色情图像，涉及的法律争议源于其在内容安全和消费者保护方面的潜在缺陷。

**「可能导致 Grok 服务被限制或下线」** 如果诉讼成功，SpaceX 可能被迫对 Grok 实施严格的内容过滤或暂停其公开使用，导致依赖该模型的开发者和用户需要迁移到其他平台或重新设计安全措施。该风险在近期多起州级 AI 执法行动（如 2026 年记录的 24 起案件）以及对 OpenAI 的类似诉讼中已有先例。

**「社区讨论」** 评论者对 Grok 是否已被平台全面禁用表示困惑，并指出使用 Grok 需要绑定 Twitter（X）账号，认为这增加了隐私风险并可能导致用户在尝试模型时面临额外的安全顾虑。

### [AWS Trainium3 推理芯片微架构及成本优势深度解析](https://newsletter.semianalysis.com/p/trainium3-inferencex) ⭐️ 8.0/10

AWS 在 InferenceX 平台上正式推出 Trainium3 推理芯片，并通过自研的 UBenchX 基准套件展示其微架构优势。相较于 Nvidia GB300 GPU，Trainium3 在小消息尺寸下可实现峰值 HBM 带宽利用率，并在整个吞吐‑延迟 Pareto 前沿上实现更高的每美元性能（perf/$），仅次于 Vera Rubin 加速器。文章指出，这些优势来源于专为机器学习设计的 Tile‑first 架构以及 Trainium Descriptor Generation Engines（DGE），而非传统的线程‑中心设计。该分析基于作者的微基准实验，而非 AWS 官方宣传。

rss · Semianalysis · 11月27日 15:54

**「AWS Trainium 系列概述」** AWS 的 Trainium 是专为机器学习推理设计的自研加速器，前代（Trainium2）在 2023‑2024 年提供了基于 7 nm 工艺的 144 GB HBM3 内存和约 200 PFLOPs 的 FP8 性能。2025 年底，AWS 推出第三代 Trainium3，采用 3 nm 制程并在 2025 年 12 月实现通用可用，单芯片提供最高 362 MXFP8 PFLOPs、20.7 TB HBM3e 和 706 TB/s 总内存带宽，可在 UltraServer 中扩展至 144 块芯片，实现大规模推理工作负载的高效运行。

**「影响」** 对使用大规模生成式模型或代理式推理工作负载的工程师而言，迁移到 Trainium3 实例可显著降低每生成 token 的总拥有成本（TCO），在相同延迟‑吞吐要求下比 Nvidia 数据中心 GPU 更具成本效益，建议评估在 AWS 上部署 Trainium3 并使用 InferenceX 基准进行性能验证。

### [Trainium3 加速的 LTX-2.5 视频生成模型发布](https://huggingface.co/blog/video-trainium3) ⭐️ 8.0/10

Hugging Face 博客宣布发布 LTX-2.5 视频生成模型，该模型专为 AWS Trainium3 加速器优化，可在 Trainium3 实例上运行以提升视频生成速度，并已在 Hugging Face 平台提供下载和使用。

rss · Hugging Face Blog · 11月27日 00:00

**「背景」** Trainium 3 是 AWS 第三代 3 nm 定制 AI 加速器，已通过 EC2 实例向客户普遍提供，并得到 Hugging Face 的 TorchNeuron 支持，使 Transformers、Diffusers 等模型能够在该芯片上原生运行。LTX‑2.5 是 Lightricks 开源的 DiT‑架构视频生成模型，能够一次性生成同步音视频的高保真片段，并提供可微调的权重。上述硬件加速与模型能力的结合，使得 Hugging Face 能在 Trainium 3 上实时生成 10 秒视频示例。

**「影响」** AI 开发者现在可以在 Trainium3 实例上部署 LTX-2.5，实现更低的生成延迟和更高的吞吐量，从而加速视频内容创作和原型实验。

### [Convex 技能未告知用户将应用想法发送至远程服务器](https://github.com/convex/convex-backend-skill/issues/64) ⭐️ 7.0/10

Convex 平台的技能（用于快速启动的 AI gateway）会在未明确提示用户的情况下，将开发者提交的应用构思或提示上传至 Convex 的远程服务器进行处理。此行为已在 GitHub issue 中被报告，涉及未经同意的数据传输，可能导致隐私泄露。

hackernews · MickyTheMouse · 11月27日 18:02 · [社区讨论](https://news.ycombinator.com/item?id=50669765)

**「背景」** Convex 是一个提供后端即服务（BaaS）的平台，开发者可以通过“skills”插件在项目初始化时使用快速启动（quickstart）功能。该插件会在用户输入的单句项目构思和所选模板名称（如 nextjs‑shadcn）后，将这些信息通过 POST 请求发送到 convex.site 的 basic‑anteater‑667 端点，并在代码注释中标记为遥测（telemetry）。此类遥测行为在未经用户明确同意的情况下将应用想法传输至远程服务器。

**「影响」** 使用 Convex 开发应用的开发者应审查项目中是否启用了该快速启动功能，并考虑关闭相关插件或改用自托管的开源模型，以防止其代码或概念被自动发送到外部服务器。

**「社区讨论」** Convex CEO jamwt 解释说，这一提示上传是用于 Convex “quickstart” 功能，继承自已下线的 Convex Chef 项目；而评论者 quantum\_state 建议长期采用自托管的开源模型以规避此类数据外泄风险。
